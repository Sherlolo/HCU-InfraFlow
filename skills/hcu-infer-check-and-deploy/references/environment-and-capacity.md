# 环境、容量与执行基线

在首次部署、环境变化或服务性能明显偏离预期时读取。这里只保存方法；节点、容器、权重和源码路径由任务 bindings 提供。

## 执行与交付分开

记录框架仓库/commit、已有补丁、实际加载模块与动态库、DTK/驱动、gfx/CU、容器镜像摘要和设备映射。用户固定的版本优先；阅读较新源码不意味着升级当前基线。选择稳定发布/插件交付，或固定基点的快速模型适配补丁。快速适配仍需约定范围内的质量、性能和功能验收。模型首次跑通后转入本仓模型优化模块；新架构/权重/缺失算子问题转入模型适配模块。

适用配方先核对版本、CLI help、实际默认值和父依赖锁。区分“源码中存在”“构建含此实现”“运行命中”和“当前模型验证通过”。不要凭环境变量名称推断它被消费者读取；有些开关按是否存在判断，字符串 `0` 也可能启用。每次变化保留生效环境和回退入口。

## 容量先于缩模

先在给定健康设备数下评估完整模型：权重分片与复制、KV cache（层数、KV heads、head dim、dtype、并发与最大在途 token）、激活、通信 buffer、图池、编译/加载峰值和工作区。EP、attention DP 等可能是重叠的 rank 分组，不能机械把所有并行度相乘。PD 分离分开预算 P/D 节点并核对总卡数；关注最慢 rank 和峰值最大的 rank。

用本仓 `simulate` 留存相同模型/工作负载、不同合法拓扑的预测；同时检查显存余量、TTFT/TPOT 与吞吐目标。预测最优仅限已比较候选和仿真假设，需真实短运行校准，不能称全局最优。工具不支持当前模型时保留模型映射缺口，由 Agent 补正确配置或明确报告阻塞，不能借用同名近似模型假装等价。

容量可行时优先完整模型。仅在用户允许且确有必要时使用缩层/缩维代理，保留被省略的层、长上下文、路由和跨层边界；代理结果不作为原模型容量或质量验收。模拟配置、调试代理和正式性能配置必须有不同身份。

## 启动、质量和测量

沿真实 launcher → 模型 registry → 权重 loader → backend 检查入口；模型名字存在不证明结构或权重映射正确。核对 shard 索引、缺失/多余权重、QKV/专家排列、tied embedding、RoPE、mask、量化 scale 和 KV layout。对固定真实请求保留参考输出、logits/token 比较与服务特性；不能只用随机 token 或 HTTP 200 作验收。

编译、图捕获、预热与稳态分开。性能运行关闭 profiler、库日志及昂贵逐张量审计；至少三次同条件测量，保存 TTFT、TPOT、吞吐、尾延迟、失败率、内存峰值及请求明细。缓存冷热、prefix 命中、流式/非流式、输入输出长度和采样参数冻结，不能把输出变短当吞吐优化。

## 异常性能的分层排查

先核单位、计时窗口和预热，再查设备健康/频率/占用、拓扑和映射、库/ABI/配置是否命中、消息/shape 是否匹配。历史带宽和峰值必须注明设备、版本、dtype 和测试口径；缺项时标未知。按证据做有界独立对照，再回模型复验，不因一次低值就重装整个栈。保留未排除原因与现场负责人交接。
