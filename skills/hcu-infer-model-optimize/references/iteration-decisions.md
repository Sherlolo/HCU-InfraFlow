# 从 profile 到下一轮决策

本页吸收 TrainFlow 的可迁移推理方法：证据驱动、初始 oracle 与最佳候选分离、上限约束、依赖/重叠和有界实验。训练 loss、反向/优化器和训练状态验证不移植为推理验收。

## 三个关联视角

- 热点—源码—空间：实际逻辑调用、阶段/rank/shape 分布、真实 backend/源码、墙钟分母、时间并集及未知量；估计 FLOPs/流量/延迟约束，说明同 shape 对照的适用条件。高占比未知项优先补证，不按熟悉程度选实现。
- 依赖—重叠：producer→consumer→join、数据就绪、等待/通信协议与最慢 rank。stream 重叠不是有效隐藏的证据；并发可能争用 CU/HBM/互联并拖慢关键计算。优先检查引擎已有调度/粒度机制。
- 融合—契约：现有调用链、guard、输出/alias/stride/dtype、可省 launch/中间量以及额外转换/buffer。图重放、融合和设备 kernel 调优分别解释收益；核对 KV/cache、mask、采样和多 stream 生命周期。

仅在已证明串行关键路径占比 f 和局部加速 s 时，用 `1/((1-f)+f/s)` 作条件性端到端估计。不可把多 rank 时间、嵌套 wrapper 和重叠 kernel 累加，也不可把多个候选预测收益相加。缺关键路径归因时写乐观界限与未知。

## 有界假设

每轮写清 observation、可证伪 hypothesis、target、支持/反证、最小实验、预算和停止点。核对真实 shape、调用频次和最慢桶；动态 token、长上下文、空专家/偏斜负载不能用单一容易测的 shape 代替。

先源码与适用性筛选，再编译/局部正确性和短时配对；有希望的候选才做完整支持范围、服务特性与正式重复。正确性不通过时停止性能资格，保留失败原件。与 CUDA 同名的接口/变量不自动代表 HCU 同等能力，检查现场 DTK/gfx 和消费者版本。

融合、graph、backend、layout 或并行变化会改变归因，应刷新当前最佳 trace；热点转移后重新排序。不同运行的映射只能提供线索，不伪造 trace/event/hash 对应。profile 关闭之后测性能，分开报告测量噪声和效应，不以固定微小百分比自动宣称显著。

## 退化与停止

连续无收益先确认证据是否过期、噪声/缓存/编译状态是否漂移、机制/依赖是否受限。恢复最佳后用新证据选择机制，不无限扫参数或机械更换语言。组合候选要整体与初始基线比较，不确定局部收益不能累加成确定增益。

停止报告包括高贡献项处置、未解释空泡/通信、显存与服务特性边界、当前最佳、初始质量和实际预算原因。过程失败/临时补丁留私有工作区；只有具有适用条件、验证与回退说明的可迁移经验才进入共享知识。
