# 从 Prof 到下一轮决策

本页把 TrainFlow 的证据闭环、同条件对照、原生能力与实现反馈、组合验收和停滞处置转成推理方法。全部决策在本仓工作流完成，不需要参考工程 checkout 或它的命令。

## 四类证据与三个比较对象

初始 oracle/性能、当前已复核最佳、待评估候选各有独立快照。每轮质量对初始 oracle，性能对当前最佳及初始基线；最新尝试不能覆盖最佳版本。比较前核对知识依据、模型/服务契约、实际制品和当前 workload。

| 证据 | 用途与边界 |
| --- | --- |
| mapping/eager 调试 trace | 恢复 Python/CPU op/dispatcher/kernel 关联；图关闭、shape/stack 采集改变开销，不用它代替正式时延 |
| formal 稳态 Prof | 在真实 graph/compile、调度与通信配置下解释调用、空泡和 rank 分布；原件、窗口和未关联项可追溯 |
| 针对性计数器/回放 | 回答选定热点的访存、资源或指令假设；replay 会扰动缓存/并发，collective 不能脱离 peer 任意执行 |
| profiler-off 重复测量 | 判断实际收益、SLA 和回退；关闭昂贵审计、debug 同步、trace hook 和密集库日志 |

Prof 的取得与解读统一交给 `$hcu-infer-analyze`。接收其 analysis、trace hashes、rank/group、窗口、capture 与原始报告；上游三张 triage 表和 TraceLens 结果用于推理，不自动证明优化结论。

## 三张关联记录

在现有报告/BOARD 维护关键行并引用原件，不复制大量原始表。每条结论区分观测事实、带条件的模型和待证伪假设。

| 视角 | 必须说明 |
| --- | --- |
| 热点—源码—上限 | 逻辑调用、phase/rank/shape/dtype 分布，真实 backend/源码；服务时间、墙钟分母、并集覆盖/未知；工作量、匹配参考、剩余空间 |
| 依赖—重叠 | producer → consumer → join，输入何时就绪，哪个 rank 暴露尾部；wait/event/collective 协议，共享 CU/HBM/NIC 与内存代价 |
| 融合—契约 | 当前调用链与已有融合 guard；可省 launch/中间量/遍历及新增转换/buffer；mask/scale、alias、KV 状态、graph/stream/fallback 边界 |

先按逻辑调用聚合贡献，再按 phase/shape/实现拆分。高占比且上限未知的项先补证；可实施首要热点不必等全模型分析完成。分析优先级和实施优先级分别说明，跳过更高贡献项需要依据。完整任务给出端到端归因覆盖（例如约定的 ≥90% 目标）及高贡献项处置；不能删掉通信、空白或未知区间凑覆盖，也不将“非通信 kernel 覆盖”冒充端到端覆盖。

FLOPs、逻辑字节、实测存储层级流量和张量常驻容量分别记录。`max(FLOPs/匹配算力, bytes/匹配带宽)` 只是带假设的理想下界，需考虑小网格、尾块、依赖、launch 和同步。理论值、同形状可达参考与当前现场值分开；未知保持未知，不能套 NVIDIA/AMD 不匹配峰值或用当前低值定义上限。

仅在已证明串行关键路径占比 f 和局部加速 s 时，用 `1/((1-f)+f/s)` 作条件性端到端估计。多 rank、嵌套 wrapper、并发 kernel 和独立候选收益不能直接相加。初版融合改变流量、并行度与资源压力后重新建模；“比 eager 快”不等于剩余空间已消失。

## 同条件对照与有界筛选

真实调用契约应包含 run/rank/phase/call、shape/stride/dtype、布局/offset、量化 scale、mask、KV 长度和 MoE token/split。相同层号不保证动态调用相同；随机稠密输入不能替代索引、路由或稀疏值域。捕获值域的诊断单独记录扰动，不把额外同步计入正式基线。

独立重放先恢复语义与状态，再比较完整 API 的设备时间和 host 提交到完成时间，包含模型实际需要的分配、copy/cast/清零、子 kernel、同步；必要的初始化与编译另记。缓存冷热、stream、图模式、频率/功率和其他作业占用一致或注明差异。

- 独立实现同样慢：检查匹配上限、实现/库选优、布局和 kernel 资源，交本仓算子模块。
- 独立正常而模型内慢：优先查计算/通信竞争、host 提交、等待、rank 到达与缓存；不直接重写 kernel。
- 设备 kernel 快而整体调用慢：查 wrapper、小 launch、分配和同步，考虑原生图或融合路径。
- 多 rank 通信慢：检查完整 split/消息量、实际拓扑和最慢 rank，区分传输、等待与到达偏斜。

每轮保存 observation、可证伪 hypothesis、target、支持/反证、最小实验、预算与停止点。先源码/容量筛选，再局部正确性和短时初筛，最后正式质量/性能和组合验证。一个假设可做有界试参，记录全部结果；初筛只能决定是否继续，不据一次最快值报告提速，也不让每个内部参数点都进入独立 flow 复核。

## 刷新、复用与组合验收

| 变化 | 需要更新 | 可复用 |
| --- | --- | --- |
| TP/EP/PD、batch/长度、精度或 workload 改变 | 分组、容量、phase/shape、语义与新比较基线；实质 context 变化使用新任务 | 未受影响的独立算子资格与来源 |
| graph/compile、fusion/backend/layout 改变 | 实际 dispatch、调用数、相关完整 Prof、KV/stream 与 fallback 回归 | 初始 oracle、未变依赖证据 |
| 单 kernel tile/stages 改变 | 当前 kernel 数值、计时与瓶颈，集成后的模型对照 | 同契约下其他算子资格 |
| 组合、显著收益/回退或热点转移 | 当前最佳的 Prof 和优先级、组合质量/内存/性能 | 历史原件按原快照引用 |
| 文档或同条件断点接续 | 先核源码/制品、输入和现场条件身份 | 一致且当前有效的证据，不机械重跑 |

本仓当前 loop 另外要求每个正式迭代使用新的 analysis ID；它允许当前轮内复用原件/未变资格，但不接受上一轮 analysis 重放。没有新采集证据时不得伪造更新字段制造“新”报告。

候选晋级先证明实际命中和局部正确性，再对固定输出与必需功能验证；改变 KV/缓存或异步行为时检查多请求、并发、long-context 和未支持形状回退。多模态/工具调用等仅在任务所需特性内验证；固定精度、模型与采样语义，不能为收益临时放宽容差或减少输出。

正式性能默认一次匹配测量，需要更强置信度时显式使用三次或更多重复，保存吞吐、TTFT、TPOT、P95、失败、内存原件和实际重复次数；必要时 A/B/A 检查漂移。有限重复或微小收益难区分噪声时保留为待验证候选，不更新已验收最佳。多个兼容改动在同一实例整体测量，失败做有界消融；不能用平均值掩盖长请求或关键桶退化。整体任务质量集在稳定里程碑按要求复验，不能用训练 loss 或几个 smoke 请求替代。

## 停滞、恢复和交付

连续无收益先检查证据过期、缓存/编译漂移、未命中、依赖/资源约束与瓶颈假设。根据新证据改变调用/布局/后端/并行或调度机制；不要无限扫参或机械更换实现语言。旧失败在版本/契约变化后可有依据地重试，必须注明新条件。

失败候选保留原件，按 loop 协议实际恢复最佳并取得本轮新 operation 的验证；远端 unknown 先核销。达到目标、接近可达参考、无稳定收益、质量/资源受限、预算或外部阻塞分别说明。未解决的显著空间附最小复现、期望/当前口径、已排查事项、知识/源码证据和下一步，交用户或既定负责人判断。

报告既保存每轮方向/性能/质量/决策，又交代热点覆盖、剩余通信/空泡、功能与内存边界、最佳快照、回退和真正停止原因。中间日志/临时补丁留私有工作区，只有已验证且具有适用条件的可复用结论进入共享知识；普通优化不自动更新 HCU 大知识库。
