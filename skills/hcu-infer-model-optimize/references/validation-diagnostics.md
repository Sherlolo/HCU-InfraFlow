# 优化验证异常与故障交接

用于优化实验结果不可信或候选失败时。沿用原始 oracle、最佳快照和当前候选，停止接受无效性能结论；数值容差与请求范围不随失败降低。

| 异常 | 动作与返回条件 |
| --- | --- |
| Prof 空、缺 rank/shape/窗口 | 交 Prof Skill 核采集/flush/过滤/工具版本；补影响结论的证据或明确缩小范围 |
| 更快但候选未命中 | 核 dispatcher、fallback、import/动态库、编译 cache；证明实际路径后重测 |
| 微测快而模型慢 | 按 [模型内外对照](operator-comparison.md) 查完整 API、争用、暴露路径和临时内存 |
| 波动大或只有偶尔最快 | 查共享负载、预热、cache/长度分布、频率、计时；增加配对重复，报告无法分辨的收益 |
| 输出变化/NaN、OOM、运行失败、hang 或崩溃 | 交故障 Skill 保存首错与失败请求，定位、修复并回归；候选保持失败/未完成 |
| 去掉 profiler 后现象改变 | 查采集同步、分配与时序扰动；回真实 serving 形态复验 |

故障交给 `$hcu-infer-diagnose-and-fix`，提供 context/epoch/attempt、当前候选及最佳快照、原失败请求、日志/trace、初始 oracle、质量与性能合同。明确实现缺口时再由诊断结果交适配或算子开发。候选被拒绝时按模型循环提交本轮真实恢复验证，不能用旧基线或重启日志代替。

修复后先重放原失败样本，补受影响的 shape/rank/graph/KV/并发边界；按模型循环完成短/长×单请求/并发精度、必需特性、profiler-off 性能和候选 Prof，再独立复核。仅缓解/未复现/缺工具分别记录，不将它们标成根因修复。

效率超过条件上限时先查单位、FLOPs/流量、缓存、dtype/指令、分母和参考条件。预算耗尽或库工单提交不等于达到硬件上限；保留已验最佳及有价值受阻项。依据 TrainFlow validation-diagnostics 改写，模型正确性以推理输出及状态为准。
