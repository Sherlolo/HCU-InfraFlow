# 热点优先级、性能上限与证据刷新

用于决定先分析什么、是否需要新算子、何时继续或停止。算子执行交接见工程 `docs/operator-development.md`。

## 形成可解释的队列

固定模型、工作负载、候选源码、设备、rank、阶段和稳定窗口。prefill、decode 和混合服务分别解释；多 rank 时先核 process groups、代表 rank 与时钟基准。以端到端墙钟为分母，单独列 GPU 服务时间、区间并集、暴露通信、host 提交/调度、空白和未归因项。不能累加包装 op、子 kernel 或并行 rank 得到“总延迟”。GPU 空白本身不能区分排队、同步、CPU 提交与无流量。

先按逻辑调用链聚合，再按 shape/dtype/stride/phase/实现细分。报告主要贡献项和累计覆盖；完整优化目标可约定约 90% 的端到端归因覆盖，但不能删去通信和空白凑比例，也不把覆盖指标作为启动一个已明确候选的前置阻塞。高贡献且上限未知的项先补分析，不能因易写优先实现小热点。

每项记录：贡献与分母、调用次数和源码、输入/输出与 alias 契约、瓶颈依据、匹配参考、可消除工作、风险、下一动作、跳过更高贡献项的理由。分析优先级与实现优先级可以不同。先检查已有引擎/库是否支持但未命中；融合、调参和新 kernel 都由证据触发。

## 性能上限

`max(FLOPs / matched_compute_rate, bytes / matched_bandwidth)` 是带假设的理想时间下界。匹配 gfx/CU、精度、指令类型、shape 和流量层级；小 GEMV、规约、除法不能套大 GEMM 峰值。将理论值、同条件独立参考、本次观测分别列出；未知不能补成峰值，也不能用本次低效基准定义上限。

逻辑读写字节、常驻张量容量、实测 HBM/L2/LDS 流量分别计算，注明 MB/GB 或 MiB/GiB。考虑尾 tile、padding、小网格、launch、同步、串行依赖、寄存器/LDS/scratch、布局和缓存。低算术强度只是带宽假设；算力和带宽都低时检查延迟、并行度与提交，不直接认定带宽瓶颈。

`调用数 × max(当前时间 − 参考时间, 0)` 只估计服务时间空间。关键路径和重叠未知时不能当作端到端可兑现收益。融合后重算被省中间量、额外重算、仍需写回的 KV/状态、寄存器压力和生命周期。kernel 消失不代表全部时长消失。

## 原生调优与算子迭代

沿消费者检查 scheduler/chunked prefill、图模式、attention 后端、KV/prefix cache、量化、专家路由和通信路径的真实支持条件。保留默认值、当前有效值、覆盖链、依赖/互斥项及内存代价；不要盲扫全部开关。缺底层能力时交算子模块，回接后重试受影响的配置组合。

每轮“测量 → 机制假设 → 单个改动或必要组合 → 正确性/dispatch → 干净配对计时 → 机制复核”。计算优化与通信/host 分析可并行，共享设备测量需串行或证明隔离。多个候选合并后重测共同快照，独立收益不能相加。

数值失败先保存最小输入与差异，检查索引/alias、FMA、累加精度、重结合、溢出和真实二进制。容差来自冻结契约；不能临时放宽以接受候选。静态 ISA/资源用于验证假设，不代替相同条件的实际 profiling。

## 刷新与停止

改调用链、融合粒度、调度、rank 组、dtype 或资源竞争后重采受影响 profile 并重排热点。未变的单算子契约和硬件参考可以复用，但旧端到端成绩不能贴给新快照。既保留初始基线，也保留当前最好候选，报告相对两者的变化。

停止原因包括达到目标/匹配可达参考、数轮无稳定收益、数值或资源约束、预算耗尽、缺工具/实现。无收益和失败候选也写入报告；仍有显著空间的受阻项不能标完成。最终保留必须经过固定请求质量、功能、无 profiler 重复性能与独立 flow 复核。
