# 工作区、交付与参考来源

## 独立运行

本仓包含自己的工作流代码、skills、配套文档、示例和测试；不读取 HCU-TrainFlow 或其他固定 checkout 的文件。安装后的 skill 从自身 `workspace.json.project_root` 找本仓资源；任务 Store 从 `--workspace` / `HCU_INFRA_WORKSPACE` 指定，两者用途不同。不要从安装目录的父级猜工程位置。

可选外部算子/Profiler 工具从 [hcu-infer-pilot](https://github.com/Sherlolo/hcu-infer-pilot) 获取，版本和实际路径由 `pilot_root`、`kernel_skill` 或模块的显式 binding 提供。工具缺失时报告具体缺口，不默认存在某台机器的目录。Python 离线工作流与 CPU demo 不依赖该仓存在；执行外部 skill/真实模型时需配置相应工具。TileLang 由现场显式绑定兼容技能，不能以 Triton 名称冒充 TileLang 实现。

知识库、模型权重和部署环境是使用者提供的运行资源，不是本仓源码依赖。已有安装可复用；不随任务隐式更新其他仓库或全局 skill。来源阅读、绑定验证、工具成功执行、硬件质量与性能验证是四种不同证据。

## 私有工作区和并行任务

在写入前记录本机/节点/容器的实际映射、源码工作树、构建/缓存/日志根和修改范围。并行开发按模块依赖与不相交文件拆分；共享接口由一个负责人集成。计时所用 GPU、NIC、CPU 和存储有争用时串行或证明隔离，租约只是协调记录，不是 OS 隔离。

使用 task/team/assignment 绑定实际 Agent 会话，返回产物经复核再消费。完整工作流只有一个主控与部署、优化、运维三阶段；新算子、适配和模型优化技能是阶段调用的专业模块，不另起互相竞争的主控。预算、人的指导和未知 operation 在新实验及阶段推进前检查。

大 trace、模型下载或构建前检查容量和配额。清理只涉及任务登记、可重建、无活跃/未知 writer 或 consumer 的缓存；保留源码、Store、初始基线、最佳候选、回退点、原始 trace、日志和唯一故障证据。不能因已有图表就删除原件。共享盘只由选定负责人维护，不扫描其他任务猜测可删文件。

## 交付轨道

稳定发布/插件线以用户选定框架版本与依赖锁为基点。新模型快速线可交固定基点的 example、补丁与构建/启动/验证方法；发布锁不因上游更新而改变。补丁需在干净副本可应用并复现已验证快照；已有用户补丁保留。稳定线接管前按接口、ABI、shape、dtype 和消费者差异复验，验证后才退役临时补丁。

仓库报告记录每轮方向、profile、源码、基线/候选性能、质量、复核、保留/回退原因、实际停止条件和剩余问题。中间实验留私有任务目录；共享知识仅保留可复用的适用条件、机制、来源、验证范围和回退方式。没有硬件运行时明确写“协议/CPU 验证”，不能据生成报告声称模型提速。
